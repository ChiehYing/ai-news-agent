## 1. The 5 Principles Behind Agent-Native Software Architecture

`Agent` `Architecture` `AI`

**來源：** DEV.to | [原文連結](https://dev.to/clawgear/the-5-principles-behind-agent-native-software-architecture-5d0e)

### 摘要

文章提出五大代理原生架構原則，強調「平等」(parity)、粒量 (granularity)、透明度、可控性與可逆性。它說明代理必須能直接完成使用者透過 UI 能完成的所有操作，而不是只剩下說明功能限制的回覆。粒量建議使用原子工具（讀檔、寫檔、執行指令）組合而非「神工具」，以保持可組合性。透明度要求展示代理的執行步驟與決策原因，讓使用者能即時監控並干預。可控性與可逆性則提供暫停、確認與備份機制，避免不可預期的破壞。

**Key Insight:** 平等是基礎，只有當代理能以與使用者相同的結果達成任務時，才能真正成為自主的代理系統。

### 學習筆記

在實作自己的多代理協調系統時，先確認每個使用者可執行的操作都有對應的原子工具，確保 parity；設計工具時保持原子化，便於組合；在代理思考過程中加入顯示步驟與不確定性的訊息；對不可逆操作加入確認機制與備份，提升可控性與可逆性。

## 2. AI Agents Memory Patterns: Working, Episodic, Semantic, and Reflective Memory

`Memory` `Agent` `RAG`

**來源：** DEV.to | [原文連結](https://dev.to/_6638a39c349d7e9c85ee20/ai-agents-memory-patterns-working-episodic-semantic-and-reflective-memory-279o)

### 摘要

文章探討 AI 代理的四種記憶模式：工作記憶、敘事記憶、語義記憶與反思記憶，並提供具體實作策略。工作記憶透過滑動窗口直接放入上下文，簡單有效；敘事記憶將重要交互存入向量資料庫，配合時間衰減提升相似性檢索；語意記憶以知識圖識保存結構化事實，便於精確查詢；反思記憶則定期總結學習要點並回填上下文，讓代理自我改進。作者還提醒管理記憶膨脹、隱私過濾、成本與延遲等實務考量，建議先實作第一種模式作為起點。

**Key Insight:** 最實用的起點是「總結+滑動窗口」模式，只需要在每 K 條訊息後呼叫 LLM 更新總結，即可在有限上下文內保留長期對話歷史。

### 學習筆記

在自己開發的代理系統中，先實作記憶總結機制，將每 N 個交互壓縮成摘要並預置於上下文，減少向量 DB 的成本；若需要更精細的回憶，可加入向量 Episodic Memory，並在搜索時加入時間衰減；最後可加入反思週期性檢查以自我優化。
