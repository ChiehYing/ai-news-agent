### 摘要

The article argues that relying on cloud-hosted AI APIs creates fragile, privacy-risky dependencies and that modern devices are powerful enough to run models locally. It demonstrates on-device summarization with Apple's SystemLanguageModel and shows how to obtain structured output by defining Swift structs annotated with @Generable, eliminating the need for JSON parsing. **Key Insight:** Local models avoid distributed-system complexity and privacy exposure; structured typed output makes them reliable subsystems.

### 學習筆記

When building agents, use local inference for data-centric tasks, define typed response schemas, and only fall back to cloud APIs when the task demands models larger than what fits on the device.

## 2. Running local models on an M4 with 24GB memory

`LocalModels` `Quantization` `Hardware`

**來源：** Hacker News | **評分：** 167 | [原文連結](https://jola.dev/posts/running-local-models-on-m4)

### 摘要

The author details the practical setup for running LLMs on a 24 GB MacBook Pro, comparing Ollama, llama.cpp and LM Studio, and describing the trade-offs of different quantizations. They recommend the q8_0-mtp quant with thinking-mode settings (temperature 0.6, top_p 0.95, etc.) for coding assistance, noting ~40 tokens/sec performance and 128K context capability. Real-world examples include fixing lint warnings and resolving Git conflicts, showing that local models can act as competent research assistants despite occasional loops. The post also warns that extensive tuning can consume more time than the actual work.

**Key Insight:** Proper quantization (e.g., q8_0-mtp) and thinking-mode configuration unlock usable speed and context length on limited-memory machines, making local agents viable for step-by-step coding tasks.

### 學習筆記

Start with a q8_0-mtp model, enable thinking mode via config, and iterate on temperature/top_p settings; use the model for incremental tasks like lint fixes or conflict resolution rather than wholesale code generation.
