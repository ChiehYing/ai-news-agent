## 2. We tested super-resolution pre-filter for LPR OCR. It did nothing

`LPR` `SuperResolution` `OCR` `AI`

**來源：** Hacker News | **評分：** 4 | [原文連結](https://www.wink.co/documentation/Neural-Super-Resolution-Pre-Filter-LPR-2026)

### 摘要

文章測試了超解析作為車牌辨識（LPR）OCR 的預處理步驟，使用 18,000+ 標註作物進行 A/B 比較。結果顯示 SR 模型（包括 42K 參數自訓練與 Real-ESRGAN 1.21M 參數預訓練）皆未提升字符正確率，甚至產生幻覺字符。此外，實際上大部分低解析度作物已被多工作票選機制忽略，SR 增強不會改變最終的辨識結果。因此，對於擁有完整訓練流程的開發者而言，無需額外的 SR 處理，直接在低解析度資料上訓練 OCR 更為有效。

**Key Insight:** 在 LPR OCR 開發中，超解析無法提供真實資訊，僅會產生幻覺，若能在低解析度數據上訓練 OCR 則更為有效。

### 學習筆記

在構建 agent 或 RAG 流程時，應直接在原始資料上訓練模型，避免使用可能引入錯誤的預處理步驟，以維持輸入資訊的完整性。

## 4. I Tested 5 AI Coding Agents — Only 2 Are Worth Your Time

`AI` `CodingAgent` `Cursor` `Windsurf`

**來源：** DEV.to | [原文連結](https://dev.to/hopkins_jesse_cdb68cfa22c/i-tested-5-ai-coding-agents-only-2-are-worth-your-time-pgn)

### 摘要

作者針對 Cursor、Windsurf、Dev CLI、Amp Code、GitHub Copilot Workspace 5 個 AI 程式碼代理進行了為期四小時、412 個提交的實測，測試包括完成度、人工修正時間與 API 費用。結果顯示 Cursor 以 100% 完成率、45 分鐘修正時間、$3.20 費用奪冠，Windsurf 以 100% 完成率、52 分鐘、$2.80 緊隨其後，兩者皆比其他工具更可靠且成本更低。作者發現 Cursor 在 repository index 理解上更優，而 Windsurf 的提前詢問機制能有效避免錯誤決策。因此，這兩款工具在實務開發中最值得採用。

**Key Insight:** 在 AI 程式碼代理的實測中，Cursor 由於深度 repository 理解，Windsurf 則以提前詢問避免錯誤，兩者在完成度、修正時間與成本上皆表現最佳。

### 學習筆記

在開發自己的 Agent 時，可優先使用 Cursor 以獲得完整的上下文索引，或採用 Windsurf 的提前詢問機制確保決策正確，並以成本與修正時間作為評估指標。

## 6. I Let AI Write My Git Commits for 30 Days — The Data Was Messy

`Git` `Commit` `AI` `Automation`

**來源：** DEV.to | [原文連結](https://dev.to/hopkins_jesse_cdb68cfa22c/i-let-ai-write-my-git-commits-for-30-days-the-data-was-messy-38bi)

### 摘要

作者在 30 天內使用本地 quantized 7B Qwen2.5-Coder 模型自動生成 Git 提交訊息，總計產出 412 個提交。實驗顯示約 72% 的訊息可直接接受，20% 需要小幅編輯，7% 需要完全重寫，主要問題在於模型在大規模變更時會產生幻覺或遺漏資訊。透過降低溫度與加入少數幾 Shot 示例，可顯著提升生成訊息的可用率與一致性，儘though仍需人工審核以確保正確性。此實驗證明在隱私與成本敏感的情境下，使用本地 LLM 生成 conventional commit 可減少認知負荷，但仍需謹慎管理錯誤率。

**Key Insight:** 透過低溫度與少 Shot 示例、人工審核機制，可大幅提升 AI 生成的提交訊息的可用率並減少錯誤，是實務中值得採用的最佳實踐。

### 學習筆記

在自己的開發流程中，可採用類似的本地 LLM 生成提交訊息的腳本，設定低溫度與少數範例，並加入人工審核步驟，從而在保持隱私與降低成本的同時提升 commit 訊息的質量。
