## 1. Rewrite Bun in Rust has been merged

`Bun` `Rust` `Rewrite`

**來源：** Hacker News | **評分：** 461 | [原文連結](https://github.com/oven-sh/bun/pull/30412)

### 摘要

Bun 團隊已將 Bun 的核心重寫為 Rust，並在主分支合併，測試通過並修復多個記憶體泄漏與測試不穩定問題。相較於原始實作，二進位體積縮小 3~8 MB，效能基準呈現中性至加速提升。新實作保留相同架構與資料結構，僅減少對少數第三方庫的依賴，且不使用 async Rust。開發者可透過 `bun upgrade --canary` 測試此 Canary 版本，並提供即時回饋以改善後續的穩定版本。

**Key Insight:** 透過 Rust 重寫可在編譯期捕捉記憶體錯誤，同時減少二進位大小並提升效能穩定性。

### 學習筆記

在構建自家的 agents 時，可參考此案例將關鍵模組遷移至 Rust，利用編譯期檢查減少运行時記憶體錯誤，並保持 API 兼容性；若想降低二進位體積與提升效能，可採用 Canary 版升級策略，在測試環境驗證後逐步推廣。

## 6. Unlocking asynchronicity in continuous batching

`ContinuousBatching` `Async` `GPU` `Inference`

**來源：** HuggingFace Blog | [原文連結](https://huggingface.co/blog/continuous_async)

### 摘要

文章說明連續批次（Continuous Batching）傳統上是同步的，CPU 與 GPU 交替工作，導致高達 24% 的 GPU 閒置。透過 CUDA 流（stream）將 CPU 批次準備與 GPU 計算同時進行，可讓 GPU 始終滿載，顯著提升推理速度。示範了如何使用非預設流、事件（event）與非阻塞傳輸，構建真正的異步批次迴圈，並提供了實作細節與效能測試結果。

**Key Insight:** 透過 CUDA 流實現 CPU 與 GPU 的同時工作，可消除同步批次的空閒時間，將 GPU 的使用率提升至約 100%。

### 學習筆記

若你在部署大量 AI 任務（如 agents 生成），可參考此技術將批次準備與模型推理分散到不同 CUDA 流，減少 CPU‑GPU 間的等待，特別是在使用本地 Ollama 模型或遠端 API 時，可透過多執行緒或多進程實現真正的異步化，提升吞吐量。

`RAG` `Chunking` `PDF` `VectorDB`

**來源：** DEV.to | [原文連結](https://dev.to/ramya_perumal_e93721ef2fa/rag-sliding-window-token-based-chunking-and-pdf-chunking-packages-18nd)

### 摘要

文章說明了 sliding window chunking（滑動視窗切分）以及 token-based chunking（基於 tokens 的切分）與 PDF 切分的各種技術與庫。包括 TOON、LLMLingua 等壓縮格式，討論它們在 token 節省與檢索多樣性上的取捨，並說明如何在 PDF 中使用 PyPDFLoader、PyMuPDF 等工具進行文字抽取與分Chunk，最後示範如何將Chunk嵌入向量資料庫以供 RAG 使用。
