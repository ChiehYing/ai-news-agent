## 1. Bun.Image

`Image` `Bun` `Performance`

**來源：** Hacker News | **評分：** 16 | [原文連結](https://bun.com/docs/runtime/image)

### 摘要

Bun.Image 提供了一條鏈式的圖像處理流水線，支援 JPEG、PNG、WebP、HEIC、AVIF 等多種格式的解碼、縮放、旋轉與重新編碼。它基於 libjpeg-turbo、spng、libwebp 以及 SIMD 函數庫，實現零 npm 依賴與無原生添加式建置，工作在背景執行緒中，避免阻塞 JavaScript 執行緒。開發者可以透過 Bun.file()、Bun.s3() 或緩衝區建立 Image 實例，進行Resize、Rotate、Modulate 等變換，最後以 await 方式取得 bytes、buffer、blob 或寫入檔案。此外，它還提供 placeholder 產生低品質佔位圖、progressive JPEG、以及直接用於 HTTP Response 的內容類型自動設定功能。

**Key Insight:** Bun.Image 以零 npm 依賴、在背景執行緒中運算的鏈式圖像處理管線，提供高效的多格式轉換與佔位圖生成功能。

### 學習筆記

在開發智能代理時，可將 Bun.Image 用於即時處理使用者上傳的圖像，利用其非阻塞特性降低回應延遲；亦可直接作為 HTTP 回應內容，簡化服務端代理的實作。

## 2. Making deep learning go brrrr from first principles (2022)

`Deep Learning` `Performance` `Compute` `Memory` `Optimization`

**來源：** Hacker News | **評分：** 143 | [原文連結](https://horace.io/brrr_intro.html)

### 摘要

文章解釋深度學習效能可分為三個面向：計算 (FLOPS)、記憶體帶寬與其他開銷。透過判斷當前工作負載是屬於計算受限、記憶體受限或其他 overhead，開發者能精準選擇優化方向。最終，提升效能的關鍵在於減少不必要的資料搬移，讓 GPU 更多時間執行矩陣運算。作者亦討論了固定點陣化與效能倍增的差異，以及在不同硬體架構上的實際限制。

**Key Insight:** 效能提升的關鍵在於先定位當前工作負載的瓶頸——是計算、記憶體帶寬還是其他開銷。

### 學習筆記

在構建智能代理時，先用 profiling 工具判斷瓶頸，若是記憶體帶寬受限，則應減少不必要的資料搬移；若是計算受限，則考慮模型壓縮或 operator fusion 以提升 FLOPs 利用率。

## 3. Towards Speed-of-Light Text Generation with Nemotron-Labs Diffusion Language Models

`Diffusion` `LLM` `Inference` `NVIDIA` `Performance`

**來源：** HuggingFace Blog | [原文連結](https://huggingface.co/blog/nvidia/nemotron-labs-diffusion)

### 摘要

Nemotron-Labs Diffusion 是一系列開放權重的語言模型（3B、8B、14B），可在同一檢查點上同時支援自回歸、擴散與自我猜測三種生成模式，無需修改應用程式即可切換。擴散模式一次生成 32 個 token，循環去噪，相較於傳統自回歸可提升 2.6–6 倍的吞吐量，自我猜測模式更能在相同硬體上達到約 6.4 倍的 token 速率，且在溫度 0 下保持與自回歸相似的準確度。模型首先在 1.3T token 上進行預訓練，再以結合自回歸與擴散目標的方式微調，保留原有能力同時獲得平行 decoding 的優勢。這些模型採用 NVIDIA 的 Nemotron 開放模型授權，並支持未來的 SGLang 整合，方便部署。

**Key Insight:** 單一模型同時支援三種生成模式，且在自我猜測模式下可達約 6.4 倍的推理速度而不影響精度。

### 學習筆記

在開發代理系統時，可優先試用自我猜測模式以在批次大小為 1 的情況下取得接近 6 倍的回應速度，並透過 SGLang 的即將上線支援簡化部署流程。

## 6. From Tokens to Attention: My First Real Mental Model of LLMs

`LLM` `Attention` `Transformer` `MentalModel`

**來源：** DEV.to | [原文連結](https://dev.to/upayanghosh/from-tokens-to-attention-my-first-real-mental-model-of-llms-54j9)

### 摘要

文章從最基礎的字符級別編碼說起，說明文字如何被轉換為唯一的 ID，然後透過 embedding 產生向量表示，再加入正弦/余弦位置編碼解決詞序問題。接著解釋注意力機制是如何根據 query、key、value 為每個 token 加權混合上下文，並透過遮蔽機制保證只能看到先前的 token。最後指出這些步驟組成了 transformer 的核心流程，使模型能夠預測下一個 token 的概率分布。整體流程把文字轉換為向量、利用位置資訊與加權上下文後，再輸出概率分布決定下一個詞。

**Key Insight:** 注意力機制本質上是對上下文的加權混合，決定模型在預測下一個 token 時關注哪些先前的資訊。

### 學習筆記

在設計智能代理時，了解注意力如何加權上下文可以協助你撰寫更精確的提示詞，並預期模型的聚焦行為，從而提升回應的相關性。
