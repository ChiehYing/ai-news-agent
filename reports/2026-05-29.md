## 2. Building durable workflows on Postgres

`Postgres` `Durable Workflows` `Database`

**來源：** Hacker News | **評分：** 244 | [原文連結](https://www.dbos.dev/blog/postgres-is-all-you-need-for-durable-execution)

### 摘要

文章說明耐久工作流程可以直接在 Postgres 中實現，無需額外的協調服務。透過定期檢查點存儲於資料庫，讓工作流在失敗時可從最新檢查點恢復。使用 Postgres 的可擴展性、可用性與觀測功能，可簡化可靠執行的設計，並利用 SQL 查詢實現即時監控與分析。此設計減少單點故障，提升安全性與運營簡單性。

**Key Insight:** 使用資料庫本身作為協調與檢查點儲存，可完全消除外部 orchestator，從而簡化架構並提升可靠性。

### 學習筆記

對於正在學習 Agent 框架的你，可將 Postgres 設為持久化層，將每一步的執行結果以 checkpoint 方式寫入表格，這樣在模型失敗時能夠從最後一步繼續，減少重新啟動的複雜度。結合 SQL 查詢監控，使你能夠在 Python 環境下輕鬆追蹤與調試 Agent 的執行流程。

## 3. Show HN: Ktx – Open-source executable context layer for data agents

`ktx` `Data Agents` `Context Engineering`

**來源：** Hacker News | **評分：** 52 | [原文連結](https://github.com/Kaelio/ktx)

### 摘要

ktx 是一個開源的上下文層，可自動從 Wiki、dbt、Looker 等來源提取公司知識，建立可搜索的語義層，並解決 join 陷阱與矛盾。它提供 CLI 與 MCP 介面，讓像 Claude Code、Codex 此類代理能夠使用統一的 SQL 查詢而不必自行探索資料庫。使用者需先安裝、設定、建立上下文，然後即可在代理中查詢已建構的度量。此工具適用於需要大規模、可重用的度量定義與資料來源的情境。

**Key Insight:** ktx 透過自動化的語義層構建與矛盾偵測，讓代理能夠直接使用預先驗準的 SQL，而不必重新編寫，顯著提升查詢一致性與開發效率。

### 學習筆記

在開始構建自己的代理時，可先使用 ktx 為資料倉儲生成統一的上下文，接著將生成的度量與 join 圖導入你的代理 pipeline，這樣代理在查詢時就能直接使用已驗證的 SQL，減少錯誤與重複工作。
