## 1. Zero-Touch OAuth for MCP

`MCP` `OAuth` `Enterprise Auth`

**來源：** Hacker News | **評分：** 58 | [原文連結](https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/)

### 摘要

Enterprise-Managed Authorization（企業管理授權）擴充功能讓 MCP server 的授權管理能夠透過單一身份提供者集中控制，使用者只要第一次登入就會自動取得所有授權的服務，免除每個應用的 OAuth 設定。此機制提供中心化的政策與稽核功能，避免個人與企業帳戶的混用，並已獲 Anthropic、Microsoft、Okta 等早期採用，提升企業安全與採用率。

**Key Insight:** Enterprise-Managed Authorization 讓組織能夠在單一身份提供者上集中管理 MCP 授權，實現零接觸設定與統一稽核。

### 學習筆記

在實作自己的 MCP 伺服器時，可考慮採用 Enterprise-Managed Auth，利用身分提供者一次性授權，降低使用者每應用 OAuth 的麻煩，並在組織內部集中管理存取策略。

## 3. .gitignore Isn't the only way to ignore files in Git

`Git` `Version Control` `Gitignore`

**來源：** Hacker News | **評分：** 275 | [原文連結](https://nelson.cloud/.gitignore-isnt-the-only-way-to-ignore-files-in-git/)

### 摘要

Git 不只提供 .gitignore，還新增了 .git/info/exclude（儲存於倉庫但不版本化）和全域 ~/.config/git/ignore（機器-wide）兩種額外忽略方式；使用 git check-ignore -v  可以檢視檔案被哪個設定檔排除，並可透過設定全域 exclusion file 在所有倉庫中統一排除 .DS_Store 等雜務檔案。

**Key Insight:** Git 提供了三種不同層級的忽略檔案機制，允許更靈活的專案與全域排除方式。

### 學習筆記

在管理多個專案的時候，利用 .git/info/exclude 或全域忽略檔案可以避免將個人臨時檔案誤提交，並用 git check-ignore 快速驗證排除來源，維持倉庫清潔。
