## 1. Ternlight – 7 MB embedding model that runs in browser (WASM)

`Embedding` `WASM` `RAG` `Browser`

**來源：** Hacker News | **評分：** 27 | [原文連結](https://ternlight-demo.vercel.app/)

### 摘要

Ternlight 提供一個僅 7 MB 的嵌入模型，可直接在瀏覽器中以 WASM 運行，無需伺服器 API。它能在毫秒級速度下生成文本嵌入，支援半精度 CPU 推理。這使得隱私保護的語意搜索、離線 RAG 等應用成為可能，且不需要額外的模型下載步驟。因為是單一 npm 包，開發者可以輕鬆將其嵌入 React 等前端框架。

**Key Insight:** 7 MB 的嵌入模型在瀏覽器中以 ~5 ms 的速度運行，實現本地化、零網路的語意搜索。

### 學習筆記

由於您正在開發需要本地化嵌入的智慧體，可考慮使用 Ternlight 在用戶端進行即時語意搜索，避免資料外洩與 API 成本；透過 npm 或 Node.js 包裝取得，將 embed() 函式直接呼叫在 Python 後端或前端代理中，即可實現低延遲的索引與檢索。

## 3. Pruning RAG context down to what the answer actually needs

`RAG` `Pruning` `Context`

**來源：** Hacker News | **評分：** 36 | [原文連結](https://www.kapa.ai/blog/how-we-prune-rag-context)

### 摘要

這篇文章介紹了一種使用小型 LLM 在檢索階段為答案挑選最關鍵片段的方法，將原本需要全部上下文的成本降低約三分之一。小型 LLM 會根據五層次的評分標準（Essential、Contributing、Supporting、Tangential、Irrelevant）對每個片段進行等級評分，並給予閾值決定保留或丟棄，這樣可以在保留 96% 回覆所需上下文的同時，剔除約 68% 的不必要資訊。相較於單純的排序或 Top‑N 截斷，這種全局列表式評分能更精確地判斷片段在答案中的貢獻度。實驗顯示此技術在不顯著犧牲正確性的前提下顯著減少查詢成本與延遲。

**Key Insight:** 使用列表式 LLM 評分與固定閾值的全局裁剪，使得 68% 的上下文可以被安全丟棄，同時保持 96% 的必要回覆完整性。

### 學習筆記

在您的 RAG 管線中加入一個輕量化的裁剪步驟，讓小型 LLM 根據問題與所有 Retrieved chunks 一起評分並決定保留哪些片段，可降低 API 呼叫成本、加速響應，同時保持高回覆完整性。
