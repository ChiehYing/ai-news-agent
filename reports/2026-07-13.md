## 1. Apple's new SpeechAnalyzer API, benchmarked against Whisper and its predecessor

`SpeechAnalyzer` `Whisper` `Benchmark` `Apple` `SpeechRecognition`

**來源：** Hacker News | **評分：** 404 | [原文連結](https://get-inscribe.com/blog/apple-speech-api-benchmark.html)

### 摘要

Inscribe 針對 Apple 在 iOS 26 與 macOS 26 中推出的 SpeechAnalyzer 與前身 SFSpeechRecognizer 進行了嚴謹的現場基準測試，使用 5,559 條 LibriSpeech  utterances 比對 Whisper 各模型及舊版 API 的文字錯誤率（WER）。結果顯示 SpeechAnalyzer 在乾淨與噪音語音上皆顯著降低 WER，且比 Whisper Small 快三倍，成為目前在 Apple 設備上最佳的本地語音辨識方案。此外，舊版 API 的錯誤率是前者的四倍以上，遷移可顯著提升文字正確度與輸出品質。此項測試提供了可重現的數據，讓開發者能直接比較不同引擎在同一硬體平台上的表現。

**Key Insight:** SpeechAnalyzer 在乾淨與噪音語音上的 WER 均顯著低於 SFSpeechRecognizer 與 Whisper 小模型，且速度比 Whisper Small 快三倍，證明它是目前 Apple 設備上最有效的本地語音引擎。

### 學習筆記

如果你正在開發需要在 iOS 或 macOS 上進行本地語音辨識的功能，建議直接切換至 SpeechAnalyzer；在 RAG 或 Agent 系統中，可將其作為語音前端，減少後續模型的處理負擔，同時利用其較低的延遲與較高的準確度提升整體效能。

## 2. Show HN: Jacquard, a programming language for AI-written, human-reviewed code

`ProgrammingLanguage` `AI` `CodeReview` `Jacquard`

**來源：** Hacker News | **評分：** 32 | [原文連結](https://github.com/jbwinters/jacquard-lang)

### 摘要

Jacquard 是一種小型專門語言，旨在讓機器學習模型產生的程式碼能被人類更有效地審查與管理。語言內建副作用（effects）與有限離散不確定性表示，讓開發者能明確描述函式可能執行的操作；同時，它使用雜湊化的結構識別而非文字，確保相同功能的程式即使寫法不同也能被視為等價。Jacquard 還提供可換 handler 的機制，讓測試可以在不同環境下模擬真實互動，從而提升代理系統的可信度與可維護性。此設計讓 humans 在審查 AI 產出的程式時，能快速捕捉潛在的副作用與安全風險。

**Key Insight:** Jacquard 通過語效表示與結構同一性，使人類審查者能精確追蹤 AI 產出程式的副作用與行為，避免傳統代碼差異偵測的模糊性。

### 學習筆記

對於正在構建 AI 代理系統的開發者，可考慮採用 Jacquard 來表達副作用與效能需求，並在測試階段使用其可換 Handler 進行環境模擬，以確保代理行為在安全邊界內運行。

## 5. Directly Responsible Individuals (DRI)

`Accountability` `AI` `Responsibility` `Management`

**來源：** Simon Willison | [原文連結](https://simonwillison.net/2026/Jul/12/directly-responsible-individuals/#atom-everything)

### 摘要

本文探討了「直接負責個體」（DRI）概念，源自 Apple 的管理實務，強調在團隊中必須指定一位最終對專案成敗負責的人類。作者認為 AI 代理不宜被視為 DRI，因為機器無法承擔法律或道德上的責任，而應由特定人類承擔決策結果的追究。此概念在設計與部署 AI 系統時提供了重要的治理框架，確保每個自動化流程都有明確的人力監督與問責機制。最終，透過明確的 DRI 責任人，組織能在複雂的 AI 環境中維持透明度與信任。

**Key Insight:** AI 代理永遠不能是 DRI，因為它無法承擔法律責任；因此，在建置 AI 系統時必須明確指定人類負責人，以確保決策可追溯與倫理合規。

### 學習筆記

在設計 AI 代理系統時，應指派具備決策權限的 DRI 為負責人，確保每次自動化輸出都有明確的問責者，從而在開發、測試與部署過程中維護透明度與責任歸屬。

## 6. PVM:Give any LLM long-term memory.No API keys,no GPU,~800 lines Python.

`Memory` `LLM` `PVM` `Python`

**來源：** DEV.to | [原文連結](https://dev.to/rocky007cn/pvmgive-any-llm-long-term-memoryno-api-keysno-gpu800-lines-python-42p3)

### 摘要

PVM 提供了一種在不需要 API 金鑰或 GPU 的前提下，為任何 LLM 增添長期記憶功能的簡單實作，核心概念是持久向量記憶並透過時間衰減與 delta rule 根據使用者回饋調整記憶重量。系統不再依賴向量相似度搜尋，而是追蹤記憶的存取頻率與相關性，讓經常使用或被驗證的記憶逐漸提升權重，而閒置時間長的記憶則自動衰減，避免資料「腐爛」的問題。相較於傳統 RAG，PVM 在資料更新、錯誤修正以及多記憶體衝突的處理上更為穩定，提供了模擬人類漸進學習的機制。整個程式碼僅約 800 行 Python，易於在本地部署與整合。

**Key Insight:** PVM 通過時間衰減與使用者回饋調整記憶權重，使 LLM 能在無需外部資料庫或 GPU 的情況下持續學習與記憶，解決了傳統 RAG 的資料rotting、錯誤永久化以及衝突解決問題。

### 學習筆記

若你正在為已部署的 LLM 增添長期記憶功能，可直接使用 PVM 包（約 800 行 Python），先透過 store() 保存重要事實，之後使用 query() 取得具權重的記憶，並根據使用者的 confirm 或 correct 回饋調整權重，以實現持續學習與減少錯誤重複。
