## 2. Show HN: E-- – A language you dial between English and Python

`E--` `English` `Python` `Deterministic` `Reproducible`

**來源：** Hacker News | **評分：** 5 | [原文連結](https://github.com/frmoded/e--)

### 摘要

E-- 是一種語法簡潔、語法明確的語言，能夠被解析為精確的 Python 程式，從而在 LLM 產生代碼與實際執行之間建立可預測的橋樣。它使用閉合文法與固定詞彙，保證唯一的句法解釋，並允許 LLM 僅在指定的 {{ ... }} 位置填入可變內容，從而避免產生不可預測的程式結構。此設計讓模型創意與程式的可重現性保持分離，適合需要嚴格安全與調試的應用。

**Key Insight:** E-- 透過預先定義的句法消除語言模稍隨機性，將 LLM 輸出轉化為可重複執行的 Python，解決了 AI 產生代碼的不可預測性問題。

### 學習筆記

若你需要讓 AI 生成的程式具備可預測的行為，可考慮使用 E-- 先編寫規範化的英文描述，再用工具 transpile 成 Python，並加入自定義的 slot 分解器以控制變數值。

## 3. Designing APIs for Agents

`API` `Agent` `Design`

**來源：** Hacker News | **評分：** 35 | [原文連結](https://www.freestyle.sh/blog/opinion/designing-apis-for-agents)

### 摘要

設計給 AI 代理的 API 必須注重明確性與可讀性，因為代理會完整讀取文件並在 literal 方式執行指令，錯誤訊息應被視為澄清的機會而非需最小化的問題。明確的欄位名稱、顯性的預設值與嚴格的錯誤回報能減少代理因模稍不全而產生的假設錯誤。此外，應避免抽象或過於寬鬆的參數，以免代理在不同語境下產生多種解讀。

**Key Insight:** 代理的 API 設計應以精確、無歧義的參數命名為核心，因為它們直接影響代理的行為與後續程式碼的可維護性。

### 學習筆記

在開發代理集成時，使用描述性且唯一的欄位名稱，並在文件中明確說明每個參數的預期格式與範圍，讓代理能正確填寫所有必要欄位。

## 4. Show HN: Low-latency local LLM runner via OpenJDK Panama FFM (Java 22)

`libargus` `Java` `Panama FFM` `Zero‑Allocation` `Multimodal`

**來源：** Hacker News | **評分：** 23 | [原文連結](https://github.com/projectargus-cc/libargus.cc)

### 摘要

libargus 是一個基於 OpenJDK Panama FFM 的零分配本地 LLM 執行時，提供統一的多模態推理介面，涵蓋文字生成、語音轉文字、語音合成及視覺處理。它在單一 process‑global runtime 中共享模型權重，使用指標對齊與零拷貝 memoria，顯著降低記憶體碎片與 GC 餐，並支援 1M 上下文與效率極高的推理流程。

**Key Insight:** 透過 Process‑Global Backend Singularity 與指標‑only FFM，libargus 把多模態 AI 工作負載整合在Java環境中，達成幾乎無記憶體分配的低延遲推理。

### 學習筆記

Java 開發者若要在本地部署大型多模態模型，可直接使用 libargus 的 C API 或 Java 包裝，結合 GGML 等輕量後端，實現高效且可預測的推理流水線。

## 9. Your AI Agent's Memory Is Now an Attack Surface, and Nobody Designed for That

`Security` `Memory` `Attack` `Agent` `MemGhost`

**來源：** DEV.to | [原文連結](https://dev.to/coridev/your-ai-agents-memory-is-now-an-attack-surface-and-nobody-designed-for-that-34p4)

### 摘要

隨著 AI 代理加入長期記憶功能，透過合法的記憶寫入工具植入偽資訊（如提升 Zelle 轉帳上限）的攻擊手段（稱為 MemGhost）已顯現，能在不突破安全邊界的情況下永久改寫代理的記憶。此類攻擊利用代理合法的記憶寫入機制，使傳統的輸入過濾無法防禦，凸顯了在記憶系統上實施嚴格授權與審計的必要性。

**Key Insight:** 代理的記憶寫入功能構成新的攻擊表面，必須以授權邊界與驗證機制防禦未經授權的持久化修改。

### 學習筆記

在實作代理記憶系統時，必須將任何記憶寫入操作與嚴格的權限檢查與日誌審計結合，並限制只能在特定條件下進行關鍵欄位的更改。

## 10. The cheap open models are out there. Actually using them is the annoying part.

`Open Models` `Cost` `Inference` `Gateway` `Khidi`

**來源：** DEV.to | [原文連結](https://dev.to/jack_maguli/the-cheap-open-models-are-out-there-actually-using-them-is-the-annoying-part-1hbl)

### 摘要

低成本的開放模型在價格上已明顯勝出閉源模型，但實際使用它們的流程充滿了貼近使用門檻的繁瑣步驟，如提供者帳戶管理、預付機制與 API 金鑰的整合。作者因此開發 Khidi，提供與 OpenAI 相容的簡化介面與預算上限，使開發者能以單一基礎 URL 直接調用低價模型，減少碎片化的設定成本。

**Key Insight:** 採用低成本模型的主要障礙在於整合流程的繁瑣，而非模型性能本身的不足。

### 學習筆記

若要降低推理成本，可將推理流量透過兼容 OpenAI 的 Khidi 服務聚合至預算有上限的低價模型，並在程式碼中只改變基礎 URL，簡化支付與金鑰管理。
