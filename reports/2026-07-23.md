## 1. Show HN: Palmier Pro – Open-source macOS video editor built for AI

`AI Video Editing` `MCP` `OpenSource` `Generative AI`

**來源：** Hacker News | **評分：** 108 | [原文連結](https://github.com/palmier-io/palmier-pro)

### 摘要

Palmier Pro 是一個基於 Swift 的開源 macOS 影片編輯器，專注於 AI 整合。它內建生成式 AI，能夠直接在時間線內使用 Seedance、Kling 等模型生成影像與影片。透過內建的 MCP 伺服器，開發者可以連結 Claude、Codex、Cursor 等 AI 代理，讓多個代理共同編輯同一項目。雖然編輯器本身免費，但生成式 AI 功能需登入付費訂閱，且僅支援 Apple Silicon 的 macOS 26 (Tahoe)。

**Key Insight:** 內建生成式 AI 與 MCP 整合，讓 AI 代理能夥伴一起在視訊時間線上編輯影片。

### 學習筆記

你可以在自己的 Python 程式中呼叫 Palmier Pro 的 MCP 伺服器，利用其 API 讓 agents 直接產生或編輯影片；結合 Ollama 的 qwen3:14b 可作為內部生成腳本的模型，實作自動影片合成流水線。

## 2. Show HN: OneCLI – OSS credential gateway that keeps secrets out of AI agents

`Credential Management` `Security` `Agent Framework` `Zero Trust`

**來源：** Hacker News | **評分：** 70 | [原文連結](https://github.com/onecli/onecli)

### 摘要

OneCLI 是一個開源憑證閘道，讓 AI 代理能夠安全地使用外部服務而不暴露真實 API 金鑰。它將密鑰加密儲存於 vault，並在出站請求時由 Rust 寫成的網關替換虛假金鑰為真實金鑰，實現密鑰的集中管理與安全注入。此機制支援多種認證方式、具備圖形化儀表板，並可透過 Docker 快速部署。對於多代理協同的情境，OneCLI 提供了一種安全、可擴展的密鑰分發方案。

**Key Insight:** 安全地在不暴露真實 API 金鑰的情況下，為 AI 代理註入憑證，提升多代理工作流的安全性。

### 學習筆記

模仿 OneCLI 的安全金鑰注入方式，在你的 agent 框架中建立加密儲存的 credential vault，並在出站請求時透過 Middleware 替換偽金鑰為真實金鑰，這樣即使是多個 LLM 代理也能安全呼叫外部 API。

`Analytics` `Metrics` `Time-Series` `AI Agent`

### 摘要

Trifle 提供以儲存答案而非原始事件的分析框架，使得度量指標更具可查詢性與層次結構。它支援 Ruby、Elixir、Go 的輕量庫，並提供 CLI 與 MCP 伺服器，讓 AI 代理能直接查詢收益、背景 job 等指標。這種設計降低了對複雜基礎設施的依賴，並且可與現有資料庫無縫整合。因此開發者可在不額外建構數據管道的情況下，快速加入度量與視覺化功能。

**Key Insight:** 以儲存答案而非事件的方式追蹤指標，使 AI 代理能直接查詢階層式度量，降低底層建設成本。

### 學習筆記

使用 Trifle 的 CLI 為你的背景作業與功能使用度量寫入自定義指標，然後透過其 MCP 伺服器讓 agents 能夠直接查詢這些指標，協助在推理過程中動態調整策略。

## 5. Bringing Nunchaku 4-bit Diffusion Inference to Diffusers

`Diffusers` `Quantization` `4-bit` `Diffusion`

**來源：** HuggingFace Blog | [原文連結](https://huggingface.co/blog/nunchaku-diffusers)

### 摘要

Nunchaku 4-bit 量化技術讓 Diffusers 可直接載入 4-bit 進位的 diffusion 模型，減少 VRAM 用量幅降至約一半，同時保持相似的推理性能。原生支援消除本地 CUDA 編譯需求，使用者只需透過 from_pretrained() 即可取得模型，並在 Blackwell 系列 GPU 上達成約 1.7 秒內完成 1024×1024 圖像生成。此技術降低了硬體門檻，讓更多開發者能夠在普通消費級 GPU 上實驗大規模 diffusion 模型。

**Key Insight:** 4-bit 量化技術在 Diffusers 中的原生支援大幅降低 VRAM 需求，提升 diffusion 模型的推理速度。

### 學習筆記

若你正在用 Ollama 內部量化模型，可參考 Nunchaku 4-bit 的技巧，將大模型如 qwen3:14b 轉換為 4-bit 格式以降低 memory footprint，從而在較弱的 GPU 上運行長上下文。

## 9. Debate-Driven Development: Why AI Agents That Argue Over Your Code Catch 30% More Bugs

`Debate-Driven Development` `Adversarial AI` `Code Review` `Bug Reduction`

**來源：** DEV.to | [原文連結](https://dev.to/robertpelloni/debate-driven-development-why-ai-agents-that-argue-over-your-code-catch-30-more-bugs-491e)

### 摘要

辯論驅動開發將兩個 AI 代理分別扮演程式設計者與批判者，透過結構化的對話辨識潛在缺陷、安全漏洞與效能瓶頸。實驗顯示此方法比單一生成管線捕獲的錯誤少 30%，顯著提升代碼可靠性。作者提供了具體的 CI 流程範例與提示詞設計，說明如何在生成後自動觸發批判回報與合成步驟。此模式可作為在大規模 AI 代理程式碼基礎上實現高品質審查的基礎。

**Key Insight:** 透過 AI 代理之間的辯論機制捕捉更多錯誤，顯著降低 production bugs（約 30%）。

### 學習筆記

在你的 agent 工作流中加入 Critic-Agent，讓它根據預設的 CWE 清單對生成的代碼進行 adversarial 檢查，然後將回報的問題傳回 Synthesis-Agent 進行修復，這樣可以在 CI 步驟中自動提升代碼品質。
