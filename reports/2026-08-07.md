### 摘要

文章說明了「受限方法」概念，即只能在符合特定約束的 receiver 上呼叫的方法，透過類型等式證人在 OCaml 中實現此功能。它討論了三種實現方式：將方法移至類別外部、使用擴充方法以及使用 OCaml 的受限方法語法（雖然語法不直接支持，但可透過 type witness 編碼）。受限方法允許在方法定義上施加細粒度約束，而不必將方法放在靜態上下文中或犧牲封裝原則，從而保持面向對象的訊息傳遞機制。文章提供了實作範例，例如如何為「flatten」方法添加類型約束，以及如何使用 type equality witness 實現。這些技巧對需要在函數式與物件導向領域間架橋，或想要在 OCaml 中實作更精細型別檢查的開發者特別有用。

**Key Insight:** 受限方法可在方法層級對 receiver 施加類型約束，從而實現細粒度的型別檢查，同時維持面向對象的訊息傳遞機制

### 學習筆記

在開發 Agent 時，可借鑒受限方法的概念，將特定行為限定於特定狀態或類型的接收者上，從而避免不當調用，提升系統的安全性與可預測性。

**來源：** Hacker News | **評分：** 224 | [原文連結](https://malisper.me/how-we-made-postgres-hundreds-of-times-faster-the-query-engine/)

### 摘要

文章說明如何通過重建 Postgres 查詢引擎，將每行處理的開銷降低，從而在分析查詢上實現約三百倍的加速。重點包括批次處理（一次讀取多行）、算子融合（減少記憶體分配）以及 SIMD 向量化運算，這些技術顯著降低 CPU 與記憶體帶寬的使用量。透過最小化 Volcano 模型中的 per-row 函數呼叫，改為一次處理多筆資料，能減少解譯與函數呼叫的開銷。作者提供了實作示例，包括 BatchSeqScan、BatchSumAggregate 等，展示如何在查詢引擎中加入批次與融合，並比較性能差異。這些優化示範了在資料庫內核中，將 I/O 轉移給 CPU 後，利用批次與低層級指令提升效能的關鍵方法。

**Key Insight:** 採用批次處理與算子融合，減少每行資料的函式呼叫與記憶體分配，可大幅提升查詢引擎效能

### 學習筆記

若在構建 Agent 或處理大型資料集，可將資料分批次處理並結合算子融合以減少重複計算，這樣不僅能降低 CPU 使用率，還能縮短總體執行時間。

**來源：** DEV.to | [原文連結](https://dev.to/multigrid/shipping-a-model-inside-a-desktop-app-packaging-signing-updates-5coj)

### 摘要

文章說明在桌面應用程式中嵌入模型時，是否應將權重包含在簽名的應用程式 bundle 中，或是將其放在外部資料目錄以減少更新衝擊。如果將模型直接打包進 bundle，每次發行都必須重新簽名並重新分發巨型文件，導致更新成本高、頻率低；相反，將模型與應用分離可讓更新更輕量、只需下載較小的模型文件。記述了在不同平台（macOS、Windows、Linux）上模型存放的標準位置，如 macOS 的 Application Support、Windows 的 %LOCALAPPDATA% 等，並在沙盒環境下的限制與注意事項。介紹了簽名、inoctl 以及 notarisation 的流程，強調模型文件本身不在簽名範圍內，必須自行驗證雜湊或簽章，以保證來源可信。此外說明了模型升級的原子交換流程、 manifest 管理、暫存檔命名與驗證步驟，確保下載過程可恢復、無破損且能夠安全回滾。

**Key Insight:** 將模型與已簽名的應用程式 Bundle 分離，並於外部資料目錄中以原子交換方式更新，可減少發布體積、提升更新效率，是管理大型模型的最佳實踐

### 學習筆記

在開發需要在桌面應用內嵌大型模型的情況下，請將模型放在應用之外的平台指定資料夾，使用雜湊驗證與原子替換機制保證更新安全、避免大幅重新發布。
